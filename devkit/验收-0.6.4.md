# IslandKit 0.6.4 (16) · #96 修复验收

本轮交付了两个能读取宿主自定义时间轴的播放器适配器，并修复了车载歌词下的曲目识别。QQ 音乐和网易云普通流媒体曲目的专有原生取词仍未交付。授权目录的旧 `island.log` 有 21 条 `lyric field=`、0 条 `lyrics timeline`。它能证实使用了车载字段，无法测量播放器在哪个时刻首次发布这一句。

## 阻塞 1　自动时间轴和诊断

| #96 要求 | 本轮处理 |
|---|---|
| 播放器取词 | 从宿主播放字典读取标准及自定义歌词，包括一层嵌套字段、带时间标签的文本和字节、JSON 行数组与显式毫秒时间。命中时保存字段名和句数，经同一录音核对后由悬浮端按进度选句。发布字典里的时间轴不依赖 AssetURL。普通流媒体只发布车载单句时仍会受播放器上报时间限制。见 `players/IKPlayerLyrics.m:88`、`sources/IKMusicCenter.m:291`。 |
| 1. 未知键名 | 记录最多 40 个符合标识符形式的键及值类型，最多 8 个嵌套歌词字段。含 lyric、lrc、qrc、yrc 的未知键优先，省略数量也会显示。见 `players/IKPlaybackDiagnostics.m:42`。 |
| 2. 歌词类与方法 | `objects` 记录实际出现在歌词字段中的自定义对象类型，数组取首个元素，最多 8 项。这能把类型与具体字段联系起来。全进程私有类和方法清单未实现，单凭类名也无法判断哪个对象属于正在播放的录音。 |
| 3. 文件路径与明文判定 | 本地媒体旁的同名歌词、用户导入的文件以及用户选择的导出样本目录能生成形状报告。目录检查最多三层、256 个条目、32 个匹配文件，每个文件读至多 512 字节，用于区分时间文本、普通文本、二进制或不可读。报告用占位符保留相对层次、扩展名、大小，字符编码和文件头的判断只针对已读前缀。播放器私有容器的自动遍历未实现。见 `sources/IKMusicCenter.m:508`。 |
| 4. 独立文件 | 每个播放器保留自己的 `Library/IslandKit/playback-report.plist`，最近 24 种记录按形状去重。可在停播后从“歌词 → 导出播放诊断”导出。选中的样本目录报告可在离开当页前一并保存。见 `sources/IKPlaybackDiagnostic.m:145`、`sources/IKMusicCenter.m:493`、`sources/IKViews.swift:343`。 |

## 六条建议

| 项 | 处理与边界 |
|---|---|
| 1. persistentID 逐句变化 | 有时长及进度或队列连续性证据时，标记该录音的 persistentID 为不稳定，保留会话、封面、进度和绑定。两个显示字段同时变化时，如果同一队列位置和进度也证实连续，仍保留本曲。文件读取端会忽略已标记的 ID。明确外部 ID 冲突、队列切换或有录音切换证据的重新起播仍可换歌。见 `sources/IKLyricsTimeline.m:151`。 |
| 2. 基线歌名取错 | 已观察到换歌且第一份标题继承上一首时，在五秒内用随后到达的有效歌名纠正基线和时间轴显示歌名。两个观察端都从半句才启动、又缺少原曲信息时，歌名仍可能无法还原。见 `sources/IKLyricsTimeline.m:198`。 |
| 3. 无时长电台 | 播放器上报零时长或持续缺少时长时，节目标题可以随节目变化。电台 ID 跨节目复用时，设置页禁止绑定到旧录音。随后收到正时长会恢复歌曲处理。 |
| 4. 歌词字段日志 | 恢复 `lyric field=`，字段变化时记 0 无、1 标题、2 歌手、3 专辑。单曲的 `recording app=` 保留。见 `sources/IKMusicCenter.m:223`。 |
| 5. 两字段同时变化 | 优先已经识别的歌词字段，第一次出现歧义时优先歌手字段，保留基线歌名。该优先级是对现有车载模式的假设。见 `sources/IKLyricsTimeline.m:213`。 |
| 6. 微信头像 | 授权目录 `notif.log:766`、`:767`、`:771` 均为 `image=0`。本轮没有确定导致超时的系统服务或额外权限。头像仍沿用当前回调与阶段日志，真机结果待验。 |
